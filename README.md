# Carely — เรดาร์ดูแลผู้สูงอายุที่อยู่บ้านคนเดียว

ลูกหลานไม่ต้องกังวลว่าคุณพ่อคุณแม่จะล้มในห้องน้ำแล้วไม่มีใครรู้
**ไม่เก็บภาพหรือเสียง** ใช้เรดาร์ mmWave ติดเพดาน ซึ่งเห็นการเคลื่อนไหวได้แม้มีไอน้ำหรือปิดไฟ
และเปิด**กล้องตรวจจับการเคลื่อนไหว**เสริมได้ (ห้องนั่งเล่น) ซึ่งประมวลผลในเบราว์เซอร์ ส่งออกมาเฉพาะท่าทางและการนับท่า

ระบบทำ 2 อย่าง

1. **แจ้งเตือนการล้มและการขอความช่วยเหลือ** — ล้มแล้วไม่ลุก, อยู่ในห้องน้ำนิ่งผิดปกติ หรือกดปุ่มขอความช่วยเหลือที่จอในบ้าน
   → **หน้าเว็บลูกหลาน** (http://localhost:8000) ขึ้นหน้าต่างสีแดงเต็มจอ มีเสียงเตือนดังซ้ำ และป๊อปอัปของเบราว์เซอร์
   จนกว่าจะมีคนกด "🚗 ฉันกำลังไป" แล้วจอในบ้านจะบอกว่ามีคนกำลังมา ตอนที่ระบบสงสัยว่าล้มจะขึ้นแถบสีเหลืองนับถอยหลังให้ก่อน
   (กดปุ่ม "🔔 เปิดเสียงและการแจ้งเตือน" ในหน้าลูกหลาน 1 ครั้งหลังเปิดหน้า เบราว์เซอร์จึงจะยอมให้มีเสียง)
   ส่วน LINE OA ด้านล่างเป็นทางเลือก ไม่ต้องตั้งค่าก็ใช้งานได้
2. **ชวนลุกขยับ แก้เหงา** — นั่งหรือนอนนานเกินไป จอแท็บเล็ตในบ้านจะ**พูดชวน**ให้ลุกขึ้นมาเล่นเกม
   โดย **AI เลือกเกม**ให้เหมาะกับสุขภาพและเวลา หรือ**ลูกหลานเลือกเกมส่งมาเองผ่าน LINE** (โหมดเกม)
   และพิมพ์ข้อความใน LINE ให้เครื่องอ่านออกเสียงให้คุณยายฟังได้
3. **กล้องนับท่าในเกม** — ถ้าเปิดหน้า `/camera` ไว้ เกมยกแขนและปรบมือจะนับเฉพาะครั้งที่กล้องเห็นว่าทำจริง
   และกล้องส่งท่าทาง (ยืน นั่ง นอน ล้ม) เข้าระบบแจ้งเตือนการล้มเหมือนเรดาร์อีกตัวหนึ่ง

## ติดตั้ง (ทำครั้งเดียว)

ต้องมี `uv` (ตัวจัดการ Python) เหมือนโปรเจกต์ ElderCarely เดิม

```bash
uv sync
```

```bash
cp .env.example .env
```

แล้วแก้ `.env` ใส่ชื่อ เบอร์โทร และข้อมูลสุขภาพของผู้สูงอายุ (ส่วน LINE และ AI ใส่ทีหลังได้)

## รันเดโม (ไม่ต้องมีเรดาร์ ไม่ต้องมี LINE)

```bash
CARELY_DEMO=1 uv run uvicorn carely.server:app --host 0.0.0.0 --port 8000
```

- **หน้าลูกหลาน**: http://localhost:8000
- **หน้าจอในบ้าน**: http://localhost:8000/elder (เปิดบนแท็บเล็ตที่ต่อ Wi-Fi เดียวกัน ใช้ IP ของคอมแทน localhost แล้ว**แตะหน้าจอ 1 ครั้ง**เพื่อเปิดเสียง)
- **กล้อง**: http://localhost:8000/camera (เปิดบนคอมที่รันเซิร์ฟเวอร์ เพราะเบราว์เซอร์ให้ใช้กล้องเฉพาะ localhost หรือ HTTPS)

`CARELY_DEMO=1` ย่อเวลารอทั้งหมดให้สาธิตได้ในไม่กี่นาที:

| | ใช้จริง | โหมดสาธิต |
|---|---|---|
| ล้มแล้วไม่ลุก → แจ้ง LINE | 20 วินาที | 8 วินาที |
| อยู่บนพื้นนาน (ไถลลงช้าๆ) ถือว่าล้ม | 60 วินาที | 15 วินาที |
| ห้องน้ำ: นิ่งไม่ขยับเลย → แจ้งด่วน | 5 นาที | 25 วินาที |
| ห้องน้ำ: อยู่นาน → แจ้งเตือน | 30 นาที | 90 วินาที |
| นั่งนาน → ชวนเล่นเกม | 60 นาที | 40 วินาที |
| นอนนาน (กลางวัน) → ชวนเล่นเกม | 2 ชั่วโมง | 60 วินาที |
| ไม่มีใครกด "ฉันกำลังไป" → แจ้งซ้ำ | 5 นาที | 60 วินาที |

### บทสาธิตแนะนำ (ใช้ปุ่ม "🧪 จำลองเรดาร์" ในหน้าลูกหลาน)

1. เลือก **ห้องน้ำ** → กด **เดินเข้าห้อง** → กด **ล้ม!**
   จอในบ้านถาม "เป็นอะไรไหมคะ?" → ถ้าไม่มีใครตอบภายใน 8 วินาที การ์ดแดงจะขึ้นในหน้าลูกหลานและในกล่อง "ข้อความ LINE"
2. กด **🚗 ฉันกำลังไป** → จอในบ้านพูดว่า "ลูก รับทราบแล้ว กำลังมาหานะคะ"
3. กด **ลุกขึ้น** → LINE ได้ข้อความ "✅ คุณยายลุกขึ้นได้แล้ว"
4. เลือก **ห้องนั่งเล่น** → **เดินเข้าห้อง** → **นั่ง** รอ 40 วินาที → จอพูดชวนเล่นเกมที่ AI เลือก
5. ในการ์ด "โหมดเกม" กด **ส่งเกมนี้** ที่ "ย่ำเท้าตามจังหวะ" → กดเล่นที่จอ → กด **ขยับ/หยุดขยับ**
   หลอดพลังจะเต็มเฉพาะตอนที่เรดาร์เห็นว่าขยับ เล่นจบแล้วลูกหลานได้ข้อความ "🎉 เล่นเสร็จแล้ว"
6. พิมพ์ข้อความในช่อง 💌 → จอในบ้านอ่านออกเสียงให้ฟัง
7. เปิด http://localhost:8000/camera → ติ๊กยินยอม → **เปิดกล้อง** ยืนห่างกล้อง 2–3 เมตรให้เห็นทั้งตัว
   ส่งเกม "ปรบมือตามจังหวะ" → ที่จอในบ้านจะขึ้น "📷 กล้องกำลังนับให้ค่ะ" และนับเฉพาะตอนปรบมือจริง
   ปิดกล้องแล้วเกมจะกลับไปนับตามจังหวะเหมือนเดิม

### กล้องตรวจจับการเคลื่อนไหว (`/camera`)

ทำตามข้อกำหนดใน `CONTEXT_MOTION_CAPTURE.md` และ `VOICE_WEB.md` (Google Drive: Final coding):
ไม่เปิดกล้องเองตอนโหลดหน้า · ต้องติ๊กยินยอมแล้วกดปุ่ม · มีไฟ "กล้องทำงาน" และปุ่มหยุดตลอด ·
ประมวลผลในเบราว์เซอร์ · ไม่บันทึกภาพ วิดีโอ เสียง หรือพิกัดจุดร่างกาย · ส่งออก JSON/CSV และล้างข้อมูลได้เอง

| ขั้น | ทำอะไร |
|---|---|
| PoseNet (ผ่าน Teachable Machine pose 0.8.6) | หาจุดร่างกาย 17 จุดในภาพสี่เหลี่ยมจัตุรัส 360×360 |
| my-pose-model | ให้ความน่าจะเป็นของ นอน / นั่ง / ลุก / เดิน / ล้ม ทุกเฟรม แล้วใช้ท่าที่ชนะเกินครึ่งในหนึ่งวินาที |
| ล้ม | "ล้ม" ชนะติดกัน 2 วินาที → ส่ง `fall: true` → ตัวตรวจจับการล้มตัวเดียวกับเรดาร์ถามที่จอ แล้วแจ้ง LINE |
| ไม่มีคนในภาพ | เห็นจุดร่างกายไม่ถึง 6 จุด → ไม่ใช้ผลจากโมเดลเลย (โมเดลตอบ "ล้ม" กับภาพว่าง จึงต้องกันไว้) |
| การขยับ 0–100 | การเลื่อนของจุดร่างกายเฉลี่ยต่อเฟรม เทียบกับความยาวลำตัว (ใช้กับเกมย่ำเท้า) |
| ยกแขน | ข้อมือทั้งสองสูงกว่าจมูก = 1 ครั้ง ต้องลดแขนต่ำกว่าไหล่ก่อนนับครั้งถัดไป |
| ปรบมือ | ข้อมือห่างกันไม่ถึง 0.35 เท่าของความกว้างไหล่ = 1 ครั้ง ต้องแยกมือเกิน 0.7 ก่อนนับครั้งถัดไป |

ข้อมูลที่ส่งเข้าเซิร์ฟเวอร์: `POST /api/camera` วินาทีละครั้ง `{"presence", "moving_energy", "posture", "fall"}`
และ `POST /api/camera/rep` `{"move": "arms_up" | "clap"}` ทุกครั้งที่นับได้ เซิร์ฟเวอร์บันทึกการเปลี่ยนท่าและการล้มลงตาราง `events`
ในฐานข้อมูลเดียวกับเรดาร์ (อุปกรณ์ชื่อ `camera`) และผลเกมลงตาราง `plays`
ค่าเกณฑ์ทั้งหมดอยู่ด้านบนของ [camera.js](carely/static/camera.js) ควรปรับหลังทดสอบกับคนจริงในบูธ

> ถ้ามีเรดาร์จริงส่งข้อมูลเข้ามาด้วย ให้กด **⏹ หยุดจำลอง** ก่อน เพราะทั้งสองจะเขียนทับกัน

## ตั้งค่า LINE OA

### แบบง่าย: ส่งหาเพื่อนทุกคนของ OA (ไม่ต้องมี webhook / ngrok / ลงทะเบียน)

1. สร้าง LINE OA ที่ [LINE Official Account Manager](https://manager.line.biz) → **ตั้งค่า → Messaging API → เปิดใช้งาน**
2. เข้า [LINE Developers Console](https://developers.line.biz/console/) เลือก channel ที่เพิ่งสร้าง → แท็บ **Messaging API** → Issue **Channel access token (long-lived)**
3. ใส่ token ใน `.env` ที่ `LINE_CHANNEL_ACCESS_TOKEN` และ**ปล่อย `LINE_CHANNEL_SECRET` ว่าง** → ระบบใช้โหมด broadcast เอง
4. ลูกหลานสแกน QR เพิ่มเพื่อน OA แค่นั้น

ข้อจำกัดของแบบง่าย: ส่งถึง**ทุกคน**ที่เป็นเพื่อน OA · ไม่มีปุ่ม "ฉันกำลังไป" (เหลือปุ่มโทร) · พิมพ์ `เกม` `สถานะ` หรือข้อความอ่านออกเสียงไม่ได้
และ broadcast นับโควตาตามจำนวนเพื่อน ถ้าต้องการฟีเจอร์ครบ ใช้แบบเต็มด้านล่าง

### แบบเต็ม: มี webhook (ตอบคำสั่งและปุ่มรับทราบได้)

1. เข้า [LINE Developers Console](https://developers.line.biz/console/) → สร้าง Provider → สร้าง channel แบบ **Messaging API**
   (ระบบจะสร้าง LINE Official Account ให้)
2. แท็บ **Basic settings** คัดลอก **Channel secret** → ใส่ `LINE_CHANNEL_SECRET`
3. แท็บ **Messaging API** กด Issue **Channel access token (long-lived)** → ใส่ `LINE_CHANNEL_ACCESS_TOKEN`
4. ตั้ง `FAMILY_CODE` เป็นรหัสที่บอกเฉพาะคนในครอบครัว (กันคนอื่นแอดแล้วรับแจ้งเตือน)
5. เปิดเซิร์ฟเวอร์ให้ LINE เรียกได้จากอินเทอร์เน็ต เช่นใช้ [ngrok](https://ngrok.com):
   ```bash
   ngrok http 8000
   ```
   แล้วใส่ **Webhook URL** = `https://<ชื่อที่ ngrok ให้>/line/webhook` → กด Verify → เปิด **Use webhook**
6. ใน [LINE Official Account Manager](https://manager.line.biz) ปิด **Auto-reply messages** (ไม่อย่างนั้นบอทจะตอบซ้ำ)
7. (แนะนำ) สร้าง **Rich menu** 2 ปุ่ม: "🎮 เลือกเกม" ส่งข้อความ `เกม` และ "👵 ดูสถานะ" ส่งข้อความ `สถานะ`
8. ลูกหลานแต่ละคนสแกน QR เพิ่มเพื่อน OA แล้วพิมพ์ `ลงทะเบียน 1234` (ใช้รหัสของตัวเอง)

**คำสั่งใน LINE** (เฉพาะคนที่ลงทะเบียนแล้ว)

| พิมพ์ | ผลลัพธ์ |
|---|---|
| `เกม` | การ์ดเลือกเกม 8 ใบ กด "ส่งเกมนี้" → จอในบ้านพูดว่า "น้องต้นส่งเกม…มาให้เล่นค่ะ" |
| `สถานะ` | ตอนนี้อยู่ห้องไหน ท่าอะไร มานานเท่าไร วันนี้เล่นเกมกี่เกม |
| ข้อความอื่นๆ | อ่านออกเสียงที่จอในบ้าน เช่น "แม่คะ เย็นนี้หนูแวะไปหานะ" |
| `ยกเลิกแจ้งเตือน` | เลิกรับแจ้งเตือน |

**เรื่องโควตาข้อความ**: แพ็กเกจฟรีของ LINE OA ส่ง push ได้จำนวนจำกัดต่อเดือน (ดูในหน้า OA Manager)
ระบบจึงส่ง push เฉพาะเรื่องสำคัญ: การแจ้งเตือน การรับทราบ การลุกขึ้นได้ และผลเกมที่ลูกหลานส่งเอง
ส่วนการตอบคำสั่ง (`เกม`, `สถานะ`) ใช้ reply ซึ่งไม่นับโควตา

ถ้ายังไม่ใส่ token ระบบอยู่ใน **โหมดตัวอย่าง**: ไม่ส่งจริง แต่แสดงข้อความที่จะส่งในการ์ด "ข้อความ LINE ล่าสุด"

## AI เลือกเกม

ใส่ `ANTHROPIC_API_KEY` ใน `.env` แล้วระบบจะให้ Claude (`claude-opus-5-5`) เลือกเกมและแต่งคำชวน
โดยดูจาก: นั่งหรือนอนมานานเท่าไร · เวลาของวัน · ข้อมูลสุขภาพใน `ELDER_NOTES` ·
เกมที่เล่นไปแล้ววันนี้และเกมที่ถูกข้าม (จะได้ไม่ซ้ำจนเบื่อ)

ถ้าไม่มี key หรืออินเทอร์เน็ตล่ม ระบบใช้**กฎสำรอง**แทน (นั่งนาน → ย่ำเท้าก่อน, นอนนาน → ยกแขนก่อน, ไม่ซ้ำเกมล่าสุด) การชวนเล่นจึงไม่หยุดทำงาน
ส่งให้ AI เฉพาะข้อมูลข้างต้น ไม่มีภาพ เสียง หรือชื่อ-ที่อยู่จริง (นอกจากชื่อเรียกที่ตั้งไว้)

**เกมทั้งหมด**

| เกม | ประเภท | หมายเหตุ |
|---|---|---|
| 🙌 ยกแขนแตะฟ้า | ขยับ | นั่งหรือยืนก็ได้ 10 ครั้ง · **เปิดกล้อง: นับเฉพาะตอนยกแขนจริง** |
| 🥁 ย่ำเท้าตามจังหวะ | ขยับ | **หลอดพลังเต็มเฉพาะตอนกล้องหรือเรดาร์เห็นว่าขยับ** |
| 👏 ปรบมือตามจังหวะ | ขยับ | ช้า 8 ครั้ง แล้วเร็ว 10 ครั้ง · **เปิดกล้อง: นับเฉพาะตอนปรบมือจริง** |

คะแนนเกม = ค่าเฉลี่ยของส่วนที่ตรวจได้ (จำนวนครั้งที่กล้องนับได้ ÷ ที่ตั้งไว้ และวินาทีที่ขยับ ÷ เวลาที่ใช้)
ถ้ากล้องไม่เห็นท่าภายใน 3 เท่าของเวลาปกติ เกมจะข้ามไปขั้นถัดไป ไม่ค้าง

เพิ่มเกมใหม่ได้ใน [games.py](carely/games.py) โดยเขียนเป็นขั้นตอน (`say`, `reps`, `detect`, `seconds`, `motion`, `confirm`) ไม่ต้องแก้หน้าจอ

## ฮาร์ดแวร์

| ชิ้น | ใช้ทำอะไร |
|---|---|
| ESP32 DevKit | ต่อ Wi-Fi ส่งข้อมูลเรดาร์ทุก 1 วินาที |
| HLK-LD2410C (24 GHz) | เรดาร์จับคน ระยะ การขยับ และความนิ่ง (เห็นได้ทั้งคนที่ขยับและคนที่นิ่งแต่หายใจ) |
| MC-38 (ไม่บังคับ) | สวิตช์ประตูห้องน้ำ |
| แท็บเล็ต/มือถือเก่า | จอในบ้าน เปิดหน้า `/elder` ค้างไว้ เสียบชาร์จตลอด |

**การติดตั้ง**: ติดเรดาร์**บนเพดานกลางห้อง หันลงตรงๆ** แล้วใส่ความสูงเพดานใน `DEFAULT_DEVICES` ([config.py](carely/config.py))
ตั้งค่า LD2410C ให้ใช้ความละเอียดระยะ 0.2 ม. (ผ่านแอป HLKRadarTool) เพื่อแยกท่าได้ดีขึ้น

**การต่อสาย** และค่า Wi-Fi อยู่ด้านบนของ [carely_radar.ino](firmware/carely_radar/carely_radar.ino)
ใส่ IP ของคอมที่รันเซิร์ฟเวอร์ใน `SERVER_URL` และ `RADAR_TOKEN` ให้ตรงกับ `.env`

**ทดสอบเรดาร์กับคอมโดยไม่ใช้ ESP32**: ต่อ LD2410C ผ่าน USB-TTL แล้ว

```bash
uv run python -m carely.bridge --port /dev/tty.usbserial-0001 --device bathroom
```

**รูปแบบข้อมูลที่เซนเซอร์ส่ง** (`POST /api/radar`, header `X-Radar-Token`) — เซนเซอร์อื่นหรือกล้อง ElderCarely เดิมก็ส่งเข้ามาได้

```json
{"device": "bathroom", "presence": true, "moving_energy": 45, "still_energy": 60, "distance_cm": 120}
```

| ฟิลด์ | ความหมาย |
|---|---|
| `device` | `bathroom` / `living` / `bedroom` (ชื่ออื่นก็ได้ ระบบสร้างให้) |
| `presence` | มีคนอยู่ไหม |
| `moving_energy`, `still_energy` | 0–100 ความแรงของการขยับ / ความนิ่ง |
| `distance_cm` | ระยะจากเรดาร์ถึงจุดที่ใกล้ที่สุดของตัว |
| `height_cm`, `posture`, `fall` | (ไม่บังคับ) ถ้าเซนเซอร์รู้เอง เช่น เรดาร์ล้ม 60 GHz ที่บอก `fall: true` ได้เลย |

## ระบบตัดสินอย่างไร (ใช้อธิบายกรรมการ)

**ท่า** มาจากความสูงของส่วนบนสุดของลำตัว = ความสูงเพดาน − ระยะที่เรดาร์วัดได้ (ใช้ค่ากลางของ 3 ค่าล่าสุดกันกระพริบ)

| ท่า | ความสูงลำตัว |
|---|---|
| ยืน / เดิน | ≥ 130 ซม. |
| นั่ง | 85–130 ซม. |
| นอน (บนเตียง/โซฟา) | 45–85 ซม. |
| อยู่บนพื้น | < 45 ซม. |

**การล้ม** ([detector.py](carely/detector.py)) ต้องเกิดครบ 3 ขั้น

1. **ลงถึงพื้น**: ลำตัวลดลง ≥ 60 ซม. ภายใน 2.5 วินาทีและไปจบที่พื้น **หรือ** อยู่บนพื้นนานเกิน 60 วินาที (จับการไถลลงจากเก้าอี้ช้าๆ ได้ ซึ่งระบบกล้องเดิมจับไม่ได้)
2. **ถามก่อน**: จอในบ้านพูดว่า "เป็นอะไรไหมคะ" ให้กดปุ่ม "ฉันไม่เป็นไร" ได้
3. **ยังไม่ลุกเกิน 20 วินาที** → แจ้ง LINE ลูกหลานทุกคน ถ้าไม่มีใครกดรับทราบจะแจ้งซ้ำทุก 5 นาที (สูงสุด 5 ครั้ง)

ระบบจึง**ไม่แจ้งเตือน**เมื่อนั่งลงเร็วๆ (ลำตัวไม่ถึงพื้น) ทิ้งตัวลงนอนบนเตียง (ยังสูงกว่าพื้น) หรือก้มหยิบของ

**ห้องน้ำ** มีกฎเพิ่ม เพราะเป็นจุดเสี่ยงที่สุด: ถ้า**นิ่งสนิทไม่ขยับเลย** 5 นาที (อาจหมดสติ) แจ้งด่วน และถ้า**อยู่นาน** 30 นาที แจ้งให้ลองโทรถาม

**นั่ง/นอนนาน** นับเวลาตั้งแต่เริ่มนั่งหรือนอนจนกว่าจะ**ลุกยืน** (ขยับแขนขณะนั่งไม่นับ) ชวนเฉพาะช่วง 07:00–20:00 จะได้ไม่ปลุกตอนกลางคืน
ชวนแล้วเว้น 30 นาทีก่อนชวนใหม่ และการเล่นเกมจบนับว่าได้ลุกขยับแล้ว

**ปุ่ม 🆘 ขอความช่วยเหลือ** บนจอในบ้าน ส่งแจ้งเตือนด่วนได้ทันทีโดยไม่ต้องรอเรดาร์

## ข้อจำกัดที่รู้แล้ว

- **ค่าเกณฑ์ความสูงต้องปรับหน้างาน** ตามความสูงเพดานและความสูงของผู้สูงอายุ LD2410C วัดระยะได้หยาบ (ช่องละ 20 ซม. ที่ความละเอียดสูงสุด) จึงเหมาะกับการสาธิต สำหรับใช้จริงควรใช้เรดาร์ตรวจจับการล้มโดยเฉพาะ (60 GHz) ซึ่งส่ง `fall: true` เข้ามาได้เลย
- ระบบสมมติว่า**อยู่คนเดียว** ถ้ามีคนอื่นหรือสัตว์เลี้ยงในห้อง ท่าที่วัดได้อาจปนกัน
- ห้องที่ไม่มีเรดาร์จะมองไม่เห็น (ระบบจะขึ้นว่า "ไม่พบในบ้าน")
- **กล้อง**: โมเดลท่าทางฝึกจากตัวอย่างน้อย และยังไม่ได้วัดความแม่นยำกับผู้ทดสอบ ผลขึ้นกับแสง มุม และระยะ ควรเก็บภาพฝึกเพิ่มในบูธจริงด้วย Teachable Machine
  ครั้งแรกที่เปิดต้องต่ออินเทอร์เน็ตเพื่อโหลดไลบรารีและ PoseNet (ภาพไม่ถูกส่งออก) และเปิดกล้องได้เฉพาะ localhost หรือ HTTPS
- เสียงพูดใช้เสียงภาษาไทยของแท็บเล็ต (iPad และ Android ส่วนใหญ่มีในตัว) และต้องแตะจอ 1 ครั้งหลังเปิดหน้าเว็บ เบราว์เซอร์จึงจะยอมให้มีเสียง
- LINE webhook ต้องเข้าถึงได้จากอินเทอร์เน็ต ถ้าใช้ ngrok ให้ตั้ง `CARELY_ADMIN_KEY` ด้วย เพื่อไม่ให้คนอื่นเปิดหน้าเว็บได้

ต้นแบบสำหรับสาธิต **ไม่ใช่อุปกรณ์ทางการแพทย์** และไม่ควรใช้แทนการดูแลจริง
