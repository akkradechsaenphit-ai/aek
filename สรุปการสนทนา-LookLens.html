1. ภาพรวมระบบ

หน้าใช้ทำอะไรเปิดที่ไหน
index.htmlจอในบ้านของผู้สูงอายุ ปุ่มใหญ่ ออกกำลังกาย 3 ท่า โทรหาลูกหลาน เรียกช่วยคอมหรือมือถือ
family.htmlแอปลูกหลาน: Activities, Workout, ดูสด, แจ้งเตือน, Rewardเฉพาะคอมเครื่องที่รันเซิร์ฟเวอร์
summary.htmlหน้าสรุปสุขภาพ ส่งออก PDF ได้เฉพาะคอมเครื่องนี้
camera.htmlมือถือเป็นกล้องวงจรปิด (กล้องมือถืออย่างเดียว ไม่ตรวจจับท่าทาง)มือถือแอนดรอยที่จับคู่แล้ว
server.pyเซิร์ฟเวอร์ Python: ส่งไฟล์, ส่งต่อข้อความระหว่างหน้า, จับคู่ด้วยรหัส 6 หลักรันด้วย py server.py

2. ลำดับงานตามที่คุยกัน

ช่วงเริ่มต้น

  • รันโค้ดในโฟลเดอร์ให้เป็นเว็บ แต่ติดปัญหา Smart App Control บล็อกไลบรารี pandas/pyarrow จึงเปลี่ยนจาก Python เป็น HTML/JavaScript ทั้งหมด
  • ลดเกมเหลือ 3 ท่า (หมุนไหล่, ยกแขนขึ้นลง, ลุก-นั่งเก้าอี้) และใช้กล้องตรวจจับการทำกิจกรรม (MediaPipe) จากเทมเพลตเดิม
  • เพิ่มปุ่มโทร 1669 เมื่อล้ม ทั้งฝั่งจอในบ้านและฝั่งลูกหลาน

ปรับหน้าตาและฟีเจอร์

  • รวมแอปลูกหลานกับ Activities เป็นหน้าเดียว มีแถบเมนูล่างแบบไอคอน (ไม่ใช้อีโมจิ) และไอคอนโปรไฟล์/ตั้งค่าด้านขวาบน
  • หน้าสรุปแบบแดชบอร์ด (ห้องน้ำ ยืน นั่ง นอน ล้ม), หน้า Workout, แจ้งเตือนแบบแอปทรู, หน้า Reward
  • เพิ่มขนาดไอคอนและตัวอักษรให้ผู้สูงอายุกดง่าย, ไอคอนท่าออกกำลังกายแบบภาพคน
  • แก้โปรไฟล์ได้พร้อมเลือกรูปจากโฟลเดอร์รูป, วิดีโอคอลระหว่างจอในบ้านกับลูกหลาน, ส่งแจ้งเตือนให้ลูกหลานเมื่อคุณยายเริ่ม/จบการออกกำลังกาย
  • เปลี่ยนชื่อเป็น LookLens

เชื่อมมือถือและความเป็นส่วนตัว

  • เปิดจากมือถือผ่าน Wi-Fi หรือสาย USB tethering; มือถือเปิดกล้องได้ต้องใช้ https จึงสร้างใบรับรองในเครื่อง (make-cert.ps1)
  • จับคู่ด้วยรหัส 6 หลัก รับมือถือแอนดรอยได้ 1 เครื่อง; หน้า family และ summary เปิดได้เฉพาะในคอมเครื่องนี้
  • มือถือทำหน้าที่เป็นกล้องวงจรปิด (camera.html) ภาพขึ้นบนหน้า "ดูสด" ของ family แบบเรียลไทม์
  • หน้า summary แยกออกมา ส่งออก PDF ได้
  • ลิงก์สาธารณะผ่าน Cloudflare (1.1.1.1/cloudflared): ยังไม่ได้ทำ เพราะต้องดาวน์โหลดโปรแกรมและยังไม่ได้รับอนุญาต

แก้ภาพกล้องไม่ขึ้นและไม่เสถียร

  • กล้องไม่เปิด: มือถือเปิดแบบ http ซึ่งเบราว์เซอร์บล็อกกล้อง → ให้เด้งไป https เอง
  • ภาพวิดีโอ WebRTC ค้าง "กำลังเชื่อมต่อ" ทางสาย USB → เพิ่มทางสำรองส่งภาพนิ่งต่อเนื่อง (~5 ภาพ/วินาที) ผ่านเซิร์ฟเวอร์ และใช้ทางนี้เป็นทางหลักสำหรับกล้องมือถือ
  • ภาพหลุดบ่อย/สถานะเปิดๆปิดๆ: นับเวลาที่คอมรับสถานะจริง (ไม่ใช้นาฬิกามือถือ), หยุดดูแล้วหยุดจริง, ไม่ลองต่อ WebRTC ซ้ำ
  • หน้า family กับมือถือใช้กล้องเดียวกัน; หน้าเล่นเกมใน index.html แสดงภาพจากกล้องมือถือแทนกล้องคอม
  • แถบสีเหลืองใน index.html กระพริบ → แสดงเฉพาะตอนลูกหลานดูภาพอยู่จริง
  • หน้าแจ้งเตือนเด้ง/เลื่อน → ข้อมูลจากจอในบ้านกับสถานะกล้องมือถือไม่ทับกันอีก
  • หน้า family ว่างเปล่า → แก้ข้อผิดพลาดของโค้ดที่ผมทำพลาดเอง (คอมเมนต์ทับท้ายบรรทัด)
  • เปิดแบบไฟล์ (file:///) เชื่อมมือถือไม่ได้ → หน้าจะเด้งไป http://localhost:8090 เอง

ลบแถบกล้อง และเสียงนำออกกำลังกาย

  • ลบแถบ "กล้อง" ออกจากเมนูล่างของ index.html
  • เมื่อลูกหลานส่งเกมมา มือถือส่งเสียงสัญญาณ พูดแจ้ง แล้วเริ่มโปรแกรมเอง (ต้องแตะหน้าจอหนึ่งครั้งเพื่อเปิดเสียง); เสียงพูดนำทีละท่าและนับจังหวะเป็นภาษาไทย

อัปโหลดขึ้น GitHub

  • เตรียมโฟลเดอร์ _upload\looklens (43 ไฟล์ ~6.2 MB) โดยตัดไฟล์ลับออก: key.pem, cert.pem, pairing.json, .env, .venv
  • repo ปลายทาง github.com/akkradechsaenphit-ai/aek (public) — อัปโหลดอัตโนมัติไม่สำเร็จเพราะ Chrome ที่ผมควบคุมไม่ได้ล็อกอิน GitHub ต้องลากไฟล์อัปโหลดเอง (หน้า /upload/main)

3. วิธีใช้งานตอนนี้

เปิดระบบ: ดับเบิลคลิก เปิด LookLens.bat หรือรัน py server.py ในโฟลเดอร์ Carely (เปิดหน้าต่างค้างไว้)
คอม (ลูกหลาน): http://localhost:8090/family.html · ดูสด: ...#live · สรุป/PDF: http://localhost:8090/summary.html
มือถือ (กล้อง): http://10.10.5.17:8090/camera.html (เด้งไป https; กด ขั้นสูง → ดำเนินการต่อ แล้วกด เริ่มส่งภาพ) — ที่อยู่เปลี่ยนตามเครือข่าย ดูในหน้าต่างสีดำของเซิร์ฟเวอร์
รหัสจับคู่: แสดงในหน้าต่างสีดำ (ล่าสุด 691553 มือถือ 10.10.3.183 จับคู่แล้ว) ; เปลี่ยนมือถือด้วย py server.py --reset-pairing
ข้อควรรู้: มือถือกับคอมต้องอยู่เครือข่ายเดียวกัน (Wi-Fi ที่แยกอุปกรณ์ออกจากกันอาจเข้าไม่ถึง ให้ใช้ USB tethering แทน); เสียงพูดบนมือถือต้องแตะหน้าจอหนึ่งครั้งก่อน; ภาพจากมือถือเป็นภาพนิ่งต่อเนื่อง ไม่ใช่วิดีโอลื่น; ระบบเป็นต้นแบบสาธิต ไม่ใช่อุปกรณ์การแพทย์

4. สิ่งที่ยังค้าง

  • อัปโหลดโค้ดขึ้น GitHub (repo aek ยังมีแค่ README เริ่มต้น) — ต้องล็อกอินหรือลากไฟล์เอง และตัดสินใจเรื่อง public/private
  • ลิงก์สาธารณะผ่าน cloudflared — รอการอนุญาตให้ดาวน์โหลด
  • ระบบนับท่าอัตโนมัติยังใช้กล้องคอม ยังไม่ได้ป้อนภาพจากมือถือเข้าตัวตรวจจับท่าทาง
  • การทดสอบกับมือถือจริงในหลายอย่างยังทำได้บางส่วน (เสียงพูดนำ, การส่งเกมจากลูกหลานไปมือถือ)
